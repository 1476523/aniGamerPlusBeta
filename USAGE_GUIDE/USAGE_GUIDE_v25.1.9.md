# 使用教學：通知模板自訂與發送歷史（v25.1.9 起適用）

> 自 **v25.1.9** 起，Telegram／Discord 的每一種通知（下載完成、下載失敗、公告事件、系統事件……共 11 類）都可以自訂實際發送的文字內容，<br>
> 不再是寫死在程式碼裡的固定格式；<br>
> 同時新增「發送歷史」，可以回顧每一則通知實際送出的內容與成功/失敗結果。<br>
> 這份文件說明這兩項功能怎麼用。<br>
> 若想了解本客製版與官方 v24.6 的完整功能差異，請參閱 [README.md](README.md)；<br>
> 只想看 v25.1.9 這次版本的變更清單，請參閱 [RELEASE_NOTES_v25.1.9.md](../RELEASE_NOTES/RELEASE_NOTES_v25.1.9.md)。

## 開始之前：這個功能是什麼？

過去（v25.1.8 及更早）Telegram／Discord 通知的文字內容是寫死在程式碼裡的固定格式，例如下載完成一律是「番劇名稱 [集數]\n下載完成 XXX MB」，使用者無法調整措辭、加上自己想要的格式，或是省略/新增想看的資訊。

v25.1.9 起，「設定」→「通知設定」新增「**通知模板**」摺疊區塊，11 種通知類別（見下表）都能個別編輯：

| 分類 | 涵蓋類別 |
|---|---|
| 下載通知 | 手動任務-下載完成／下載失敗、排程任務-下載完成／下載失敗 |
| 公告通知 | 停止更新、延後更新、臨時加更、其他公告 |
| 系統通知 | Cookie失效、裝置驗證異常、新版本可用 |

> ⚠️ 這是客製強化版**獨有**的功能，模板內容存在 `aniGamer.db` 裡，**不包含**在「其他」區塊「匯出設定與排程檔」的匯出範圍內（該功能只匯出 `sn_list.txt`／`config.json`），改回官方版後這些自訂模板不會被帶過去。
> 
> CQ（酷Q）通知不套用自訂模板，維持原本固定格式，因為 CQ 是舊版遺留的通知管道，設計上就沒有獨立的格式標籤系統。

## 一、編輯通知模板

1. 進入 Dashboard「設定」頁，展開「通知設定」→「通知模板」子區塊。
2. 下拉選單「**選擇通知類別**」選定要編輯的類別（例如「手動任務-下載完成」），選定後下方文字框會自動載入該類別目前的模板內容（第一次使用時是內建預設文字）。
3. 格式工具列正下方固定顯示一排[通用字符（token）](#三通用字符token對照表)按鈕，把游標移到文字框中想插入的位置後直接按下即可插入；<br>
也可以搭配上方[格式標籤工具列](#二telegram-格式標籤怎麼用)套用格式——兩者操作方式相同，都是「選好位置/文字後按按鈕」，不用自己手打容易出錯的符號。
4. 改好後按「**儲存模板**」即立即生效，之後這個類別的通知就會照新模板發送；<br>
想先看效果再決定要不要存檔，可以按「**預覽**」（見下方[預覽功能](#四預覽功能)），<br>
想確認真的送到 Telegram/Discord 上的樣子則可以按「**模板測試**」（見下方[模板測試](#五模板測試)）。
5. 改壞了、或想不出更好的措辭時，按「**恢復預設**」可以把該類別還原成內建的預設文字（Telegram／Discord 兩個版本會一併還原）。<br>
文字框上方若顯示「**目前為預設值**」徽章，代表這個類別還沒被自訂過。

> 模板文字框下方另外有一個唯讀的「**Discord 版本預覽**」欄位：儲存模板時，<br>
> Telegram 版用的 HTML 格式標籤會自動轉換成對應的 Discord Markdown 語法並顯示在這裡，**不需要自己手動維護兩份文字**。<br>
> 真正送出 Discord 通知時使用的就是這個自動轉換後的版本。

## 二、Telegram 格式標籤怎麼用

Telegram Bot 支援用 HTML 標籤替訊息加上格式（Discord 版會在儲存時自動轉換成對應的 Markdown 語法，兩者效果相同）。<br>
編輯模板時，**選取要套用格式的文字**後按下方對應按鈕，會自動幫選取的文字包上標籤，不需要自己手打：

| 工具列按鈕 | 標籤 | 效果 | Discord 對應語法 |
|---|---|---|---|
| B | `<b>文字</b>` | 粗體 | `**文字**` |
| I | `<i>文字</i>` | 斜體 | `*文字*` |
| U | `<u>文字</u>` | 底線 | `__文字__` |
| S | `<s>文字</s>` | 刪除線 | `~~文字~~` |
| 程式碼 | `<code>文字</code>` | 單行程式碼樣式，適合短片段（指令、變數名稱） | `` `文字` `` |
| 程式碼區塊 | `<pre>文字</pre>` | 多行程式碼區塊，保留換行與空白 | ` ```文字``` ` |
| 引用 | `<blockquote>文字</blockquote>` | 整段內縮並標示引用樣式 | `> 文字`（逐行） |
| 可摺疊引用 | `<blockquote expandable>文字</blockquote>` | 內容需至少 4 行才會出現收合箭頭，不足 4 行時退化成一般引用 | 同上（Discord 沒有可摺疊引用，退化成一般引用） |
| 超連結 | `<a href="網址">文字</a>` | 超連結，把「網址」換成實際連結 | `[文字](網址)` |
| 防劇透 | `<tg-spoiler>文字</tg-spoiler>` | 點擊後才顯示內容 | `‖文字‖`（Discord 原生防雷符號，同樣是點擊展開） |

套用格式後，文字框裡看到的是原始的 HTML 標籤字元（例如 `<b>公告</b>`），這是正常現象——實際發送到 Telegram 時才會被渲染成粗體文字，不會讓使用者收到的訊息裡出現這些符號本身。

## 三、通用字符（token）對照表

格式工具列正下方固定顯示一排按鈕，依你目前選擇的類別列出該類別實際適用的 token。<br>
按鈕上顯示的是**中文說明**（例如「番劇名稱」）而不是原始的 `@字符@` 字串，比較容易一眼看懂用途；<br>
把滑鼠移到按鈕上會用提示文字（tooltip）顯示對應的 `@字符@`，把游標移到模板文字框中想插入的位置後按下按鈕，插入的就是這個 `@字符@`，發送通知時會自動替換成實際內容。<br>
每個字符詳細的用途與適用備註收在下方「**可用通用字符說明**」摺疊區塊裡（用法跟「Telegram 格式標籤說明」一樣，預設收合，點標題展開查看），完整對照如下：

| Token | 說明 | 適用範圍 |
|---|---|---|
| `@animation_name@` | 番劇名稱 | 下載通知、公告通知（系統通知沒有對應的番劇，不適用） |
| `@episode@` | 集數，例如 `[12]` | 下載通知 |
| `@file_size@` | 檔案大小（MB） | 下載完成通知 |
| `@fail_reason@` | 下載失敗原因 | 下載失敗通知 |
| `@error_message@` | 系統錯誤訊息內容 | 裝置驗證異常通知 |
| `@announcement_text@` | 公告原文 | 公告通知 |
| `@version_tag@` | 新版本標籤（tag） | 新版本可用通知 |
| `@version_body@` | 新版本更新內容 | 新版本可用通知 |
| `@download_time@` | 下載完成/失敗當下的時間 | 下載通知 |
| `@new_sn_time@` | 偵測到影片更新的時間（目前與 `@download_time@` 同值） | 下載通知 |
| `@announcement_time@` | 偵測到公告的時間 | 公告通知 |
| `@postpone_time@` | 延後後的新排程時間，只有「延後更新通知」在有解析出新時間時才有值 | 延後更新通知 |
| `@finish_time@` | 這則通知送出當下的時間，所有類別皆可用 | 全部類別（通用備援） |

> 沒有帶到值的 token 會保留原樣不清空（例如打錯字變成 `@epsiode@`），方便你發現拼字錯誤，而不是默默消失讓你以為沒問題。

## 四、預覽功能

編輯模板時按「**預覽**」按鈕，會跳出「通知預覽」視窗，用範例內容（固定的示範番劇名稱、時間等）模擬：

- **Telegram**：訊息氣泡外觀，格式標籤會直接渲染成粗體/斜體/程式碼等效果，防劇透文字點擊後才會顯示；<br>
可摺疊引用（`<blockquote expandable>`）若內容達 4 行以上，會模擬 Telegram 實際的收合互動——預設只顯示前幾行、右下角出現向下箭頭，<br>
點擊箭頭展開全文並轉成向上箭頭，再點一次收合回去（不足 4 行則維持一般引用樣式，不會出現箭頭，與[格式標籤說明](#二telegram-格式標籤怎麼用)中的規則一致）
- **Discord**：嵌入卡片（embed）外觀，標題欄位獨立顯示，內文是自動轉換後的 Markdown 效果（可摺疊引用會退化成一般引用，沒有收合互動）

預覽讀取的是文字框裡「**尚未儲存**」的內容，所以編輯過程中隨時可以按預覽確認效果，不需要先存檔，也不需要真的觸發一次下載/公告/系統事件才能看到大概的樣子。<br>
畫面樣式是模擬呈現，與 Telegram/Discord 實際 App 畫面可能有些微差異。

## 五、模板測試

「預覽」按鈕旁的「**模板測試**」按下後，會把目前選擇的類別「**已經儲存**」的模板套用範例內容，透過已啟用的 Telegram／Discord 管道**真的發送一次**，並逐一回報各管道成功/失敗的結果。

> ⚠️ 這裡用的是資料庫裡已儲存的版本，不是文字框裡還沒存檔的內容——如果剛改完模板還沒按「儲存模板」，「模板測試」測到的會是**改之前**的舊版本，請先存檔再測試。

跟「預覽」的差異：預覽是純前端模擬畫面，不會真的發出任何請求；<br>
模板測試則是實際呼叫 Telegram Bot API／Discord Webhook 送出一則訊息，能確認的不只是「排版看起來對不對」，<br>
還包括 Token/Webhook 本身是否有效、Telegram 格式標籤是否真的被正確渲染等只有實際送達才能看到的細節。<br>
測試發送的紀錄一樣會被計入[發送歷史](#六查看發送歷史)，方便之後回顧。

## 六、查看發送歷史

Telegram、Discord 通知設定區塊各自有「**查看發送歷史**」按鈕（兩邊管道的歷史紀錄各自獨立儲存，互不影響）：

1. 按下按鈕跳出「發送歷史」視窗。
2. 上方下拉選單可依「全部類別／下載通知／公告通知／系統通知」篩選，選定後右側子類別選單會列出對應的細項（例如選「下載通知」後可再篩選「手動任務-下載完成」）可再進一步篩選。
3. 按「**查詢**」列出符合條件的歷史紀錄，每筆顯示：發送時間、實際發送的完整訊息內容、以及成功／失敗（失敗時會附上錯誤原因，例如 Token 錯誤或網路逾時）。

**用途**：懷疑「這則通知怎麼沒收到」時，可以直接查歷史紀錄確認是「根本沒有送出嘗試」（例如該類別開關被關閉）、「送出了但失敗」（可看到實際錯誤原因），還是「其實有送出成功，可能是 Telegram/Discord 那邊被過濾了」，不用憑印象猜測或重新觸發一次事件來測試。

## 六、常見問題 FAQ

<details>
<summary><strong>Q: 改了模板之後，正在下載中的任務會用新模板還是舊模板？</strong></summary>

按下「儲存模板」的當下就立即生效，之後任何新觸發的通知（包含正在下載中、稍後才完成的任務）都會使用新模板，不需要重新啟動程式。

</details>

<details>
<summary><strong>Q: 防劇透（`<tg-spoiler>`）在 Discord 上是什麼效果？</strong></summary>

會自動轉換成 Discord 原生的防雷符號語法（用 `‖‖` 包住文字），效果同樣是預設模糊、點擊後才顯示內容，不需要額外設定。

</details>

<details>
<summary><strong>Q: 可摺疊引用（`<blockquote expandable>`）在 Discord 上為什麼看起來跟一般引用一樣？</strong></summary>

Discord 沒有對應「可摺疊引用」的原生功能，轉換後會退化成一般引用（每行前面加 `>`），這是預期行為，不是轉換出錯。<br>
另外 Telegram 這邊的可摺疊引用也有限制：內容需要至少 4 行才會顯示收合箭頭，不足 4 行時 Telegram 一樣只會顯示成一般引用。

</details>

<details>
<summary><strong>Q: 通知模板會包含在「匯出設定與排程檔」裡嗎？換回官方版後模板還在嗎？</strong></summary>

不會。<br>
「匯出設定與排程檔」只會匯出 `sn_list.txt` 與 `config.json` 兩個官方版看得懂的檔案，<br>
通知模板是本客製版獨有的資料表，官方版沒有對應的功能可以讀取，因此不在匯出範圍內。<br>
換回官方版後，Telegram/Discord 通知會是官方版自己原本的固定格式，跟本客製版的自訂模板無關。

</details>

<details>
<summary><strong>Q: 發送歷史會一直累積、佔用資料庫空間嗎？</strong></summary>

目前發送歷史只會持續新增、沒有自動清除舊紀錄的機制，查詢時預設最多顯示最近 200 筆。<br>
單純的文字紀錄對資料庫檔案大小的影響很小，不需要特別擔心。

</details>
